	/permissionsコマンド → Bash(touch:*) の作業（新規作成）の許可をいちいち求めてこなくなる
	→ .claude/settings.local.jsonファイルができる
			↓
	　  {
  		"permissions": {
    			"allow": [
      				"Bash(touch:*)"
    			]
 		 }
	　　}
	※ 以下のコマンドでClaudeを起動してもほとんどの作業コマンドの許可をいちいち聞いてこなくなる
	↓
	claude --dangerously-skip-permissions

	14. 実相開始：
	プロンプト：「ドキュメントを読みこみバックエンドのPhase1から実装を開始してください。ホストOSに依存しないようDockerベースで作業をお願いします。docker-compose.yamlでGoとPostgresSQLのサービスを定義し、ローカルの./backendコンテナにマウントするようにしてください。全てのAPIエンドポイントでもれなくOpenAPIのドキュメントが生成されるようにアノテーションを書いてください。
ホストOSでgoコマンドを直接実行しないでください。すべてのgoコマンドはdocker compose exec apiの中で実行してください。
CLAUDE.mdにもこのルールを追記してください。
まずはハンドラとアノテーションを全て設計してから実装に入りたいので今回作成する範囲全てのAPIをopenapiのドキュメントに起こさせたら教えてください。その後に本格実装をお願いします。use context7」
			→ docker-compose.yamlとbackendフォルダがルートにできる。backendフォルダの中には色々できる。
			→ backend/docs/swagger.jsonの中身は. 
			！！！【参考】https://editor.swagger.io/を開いて左ペインにswagger.jsonをペーストすれば右ペインに綺麗にAPI一覧が見れる。

			docker compose up で、curl http://localhost:8080/health、で　{"status":"ok"} ならOK！！！
			失敗ログ「curl: (7) Failed to connect…」なら docker compose  up で Docker起動すればよい。

	プロンプト：「PHASE1の範囲をすべて実装してください。use context7」

	ここでdocs/swagger.jsonやbackend/internal/middleware/admin.go, auth.goなどができる。
