# セキュリティレビュー 2026-11-04

- **対象:** `feature/post-images`（e2fd55e）と `origin/main` の差分
- **方法:** コードを読む静的レビューのみ。サービスの起動や攻撃の再現はしていない

## 結果

**HIGH / MEDIUM の脆弱性: なし**（このブランチで新たに入り、80% 超の確信で悪用できるもの）

## 確認した範囲

| 領域 | 結果 |
|------|------|
| 管理画面のログイン・セッション | HS256 固定、`exp` と audience が必須。署名鍵は JWT と別で、一般ユーザーのトークンは使えない |
| 管理画面の認可 | ログインと静的ファイル以外は `AdminSession` を通る。管理者の作成はサービス層で `IsRoot` を確認 |
| 管理画面の CSRF | セッションに結び付いた HMAC トークンを定数時間で比較。Cookie は `SameSite=Strict`、`OriginCheck` も有効 |
| テンプレート・XSS | `html/template` を使用し、エスケープを無効にするヘルパーなし。CSP は `default-src 'none'` |
| SQL インジェクション | 値はすべてバインドパラメータ |
| パスワードリセット | 256 ビットの乱数で、保存は HMAC ハッシュのみ。条件付き UPDATE で一回限り。リンクのベース URL は設定値で、Host ヘッダーを使わない |
| 登録審査 | `JWTAuth` / `OptionalJWTAuth` / `AdminOnly` / リフレッシュ / ログイン / Google ログインで状態を確認。自動承認は `ENV=test` のみ |
| Storage・署名付き URL | `storage_path` はサーバーが生成し、形式と拡張子は実バイトから決定（SVG / HTML は不可）。URL は GET 専用の V4 署名 |
| データ露出 | 監査ログにメールアドレス・トークン・パスワードを含まない |
| デプロイ | 最終イメージは distroless で成果物のみ。`.env.production` は公開前提の Firebase Web 設定のみ |
| フロントエンド | `dangerouslySetInnerHTML` / `innerHTML` / `eval` なし |

## 基準未満のため脆弱性としていないもの（強化の候補）

- パスワードリセットで失効するのはリフレッシュトークンのみ。盗まれたアクセストークンは最長 1 時間有効で、Swagger の説明（他端末はログアウト）と差がある
- `admin_session` はログアウトしても失効せず、盗まれると最長 8 時間有効。ルート管理者の認証情報を変更しても、`ADMIN_SESSION_SECRET` を更新しない限り既存セッションは残る
- 未承認ユーザーの公開プロフィールが `GET /users/:handle` で取得できる（公開項目のみ）

## このブランチより前からの問題（同日修正済み）

1. **`LoginWithGoogle` のアカウント乗っ取りの可能性**
   - `email` クレームを `email_verified` / `sign_in_provider` の確認なしで既存アカウントに結び付けていた
   - Firebase の Email/Password プロバイダーが有効な場合、公開の Web API キーで被害者のメールアドレスの未確認アカウントを作り、その人としてログインできる可能性があった
   - **修正:** `sign_in_provider` が `google.com` かつ `email_verified` が `true` のトークンだけを受け付ける（`verifiedGoogleEmail`）
2. **削除済み投稿の内容が見える問題**
   - リポストの要約と通知が、削除済み投稿の本文とメディアの署名付き URL を返していた
   - **修正:** `toPostSummary` が削除済み投稿に対して nil を返す。本文なしのリポストは「元の投稿は削除されました」と表示する
